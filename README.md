# Living Colors

An independent, native 3D world foundation for R2-3PO. This repository is developed separately from R2 until tested and ready for integration.

## Current implementation

- Two-story *provisional* house layout with separate upstairs rooms and continuous staircase height model.
- 640 × 480 native 4:3 desktop viewer (requires raylib) with first-person navigation, independent mouse look and a fixed **125% reference magnification**. No in-world HUD, fake screenshots, scripted tour, or imported game assets.
- Static walls, furnishings and IDs for the bed, school desk, two CRTs, bookshelf, fridge, doors, bathtub, sink, toilet and a movable school reader.
- Capsule-approximate player collision (horizontal radius + vertical interval), incremental movement, axis sliding and limited stair traversal.
- Physical object interactions (door/container open state, TV power), limited-range pickup/reposition API, reader progress and durable snapshot state keyed to stable object IDs. Save writes to a temporary file and renames on successful completion.
- Native core tests and CI, usable without a display server or raylib.

## Build

On Linux, `make test` requires only a C11 compiler and the C math library.

To run the viewer, install the raylib development package with pkg-config metadata and run:

```sh
make viewer
./build/livingcolors
```

Use **WASD** to walk, **mouse** to turn/look, **E** to toggle the focused, reachable interactive device or door, **G** to pick up the focused movable item or place the held item on a reachable support surface, **P** to advance the focused, reachable school reader's stored progress (development shortcut), **T** to store the held item in the focused open container, **R** to sit/rest on focused furniture or return to standing, **I** to inspect local environmental values, **H** to probe focused/held/support contact, **J** to inspect audible spatial cues, **F5** to save, **F9** to load, **ESC** to quit. State is saved automatically to `livingcolors.save` on normal exit. Terminal output reports interactions; the view has no HUD.

## Important limitations

This is a foundation, **not a finished Living Colors release**. Geometry dimensions and exact staircase landing alignments still need refinement. The renderer uses procedural boxes and flat colors rather than complete late-1990s textures. Outdoor streets and stores, hands and detailed manipulation, camera-to-R2 sensory integration, physics for falling items, calendar/weather integration, ownership/inventory integration, real PDF page reading, media playback, actual device operation and Android phone features are not yet integrated. Book progress is a persisted integer; it is **not** PDF parsing. The open front/back doors do not yet lead outside the world boundary. Viewer toggling checks line of sight and reach. Legacy low-level functions are retained, but subsystem clients should use the interaction API for gaze-checked actions. Stair treads are shared visual/ray geometry above a continuous movement surface. The held item is tracked by ID and omitted from its former scene position; a hand mesh and detailed container door animation remain future work.

## Architecture

`src/world.h` defines the world contract; `src/world.c` owns house layout, collisions, objects and movement; `src/save.c` owns snapshot serialization; `src/main.c` is the optional standalone viewer. The renderer reads world state, rather than replacing it with a generated description. Core state persists independently from rendering.

Prioritized plan: complete and test the two-story house, navigable environment and world persistence; extend physical manipulation and independent perception; then physically connect the street, grocery store and general/appliance store; introduce generic electronics infrastructure before integrating with R2. Other update foundations can be developed opportunistically without deprioritizing Living Colors.

## Subsystem-facing interaction API
`src/interaction.h` v4 provides renderer-independent gaze, ray intersection and reach-checked interaction against the current world. The manual viewer uses the same commands; it is not a dependency for R2. No R2 repository changes or IPC transport yet. Legacy movement, version-1 save loading, stable object IDs and low-level functions remain available. Open door panels and floor slabs now have shared physical geometry. Reading advances progress only when the reader is focused and in reach; actual document page rendering remains future work. Integration must preserve physical sensory paths, and Memory should consume confirmed events rather than treating all geometry as observed. House dimensions remain provisional.

## Physical manipulation and persistence
The G command uses a single held-object slot in the authoritative world. Picking up removes the same object from scene rays and collision, not from the object table. Placement requires a visible, reachable top surface with a complete supporting footprint and no interpenetration. Failed placements leave the held object unchanged. The legacy low-level reposition API remains available for existing callers, but new clients should use the gaze-checked API. Snapshot format 2 introduced the held ID; the loader accepts format 1 and retains the caller-provided state for new object IDs (initialize a fresh house before loading to use its defaults), but old binaries cannot read newer formats. Unknown/duplicate IDs, resized movable objects, colliding restored items and invalid held IDs are rejected. No new ownership or inventory database is introduced. Stair treads participate in sight and rendering while movement uses a continuous incline; placing items on the stairs is not implemented.

## R2-facing command receipts
`src/command.h` version 5 is the native in-process command boundary for walking, looking, and physical interactions. The viewer now uses it. R2 clients should use body-relative walking and current gaze rather than assigning arbitrary world coordinates. Each call returns invalid, rejected, unchanged, applied, or observed, with actual before/after pose and held identity. Applied object commands additionally report the affected object's before/after state and tagged world/held location; a rejected action exposes no target metadata. Correlation IDs are not durable event IDs. The receipts are evidence of in-memory world transitions only; later integration must serialize ownership, persist committed evidence and deliver it to Reality, Hands, Life Log and Experiences through their existing durable event contracts. No automatic rewards, memory claims, or synthetic experiences are generated. No IPC wire encoding is defined yet.

## Shared visual projection
`src/perception.h` defines the 640x480, 4:3, fixed 125% view contract and orthonormal camera basis. The standalone viewer derives its camera from this contract, including immediately after loading a snapshot. Spatial samples use the same basis and perspective, with normalized viewport coordinates and first-surface occlusion. Samples are geometric queries, not rendered frames, object recognition, or memories. Actual virtual frame capture and source ownership integration with Eyes remain future work.

## Physical body state and furniture
Sofa (101) and school chair (215) support seated posture; bed (201) supports resting posture. Entry requires the current visible reachable support and a clear body footprint; exit returns to the prior standing position only if clear. Walking while supported is rejected. Camera and gaze use the lowered eye height, and the command receipt records posture and support before/after. Format 3 persists posture, support ID and exit position; formats 1/2 still load as standing. Furniture capability mapping is provisional and based on stable IDs. Transitions are atomic, not animations; resting is not sleeping, and Reality continues to own needs and recovery. The school chair is newly added, with provisional geometry, and legacy snapshots do not require its ID.

## Physical storage
The fridge, bookshelf and linen closet now have finite slots and shared shelf-panel geometry for open-state sight and rendering. Closed containers occlude their contents. T stores the held item into a fitting unoccupied, reachable and unobstructed slot of an open container from its front; G retrieves a visible item using its unchanged identity. A stored object retains its progress/state and is not separately present outside the container. Body collision retains the outer container footprint. Format 4 persists parent and slot IDs; versions 1–3 still load. The receipt identifies the requested container separately from the affected item. Slots are provisional fixed geometry, no nested storage, pocket integration, container types or real food inventory ownership yet; Reality remains the future authority for ownership and purchase transactions.

## Compatibility contract
The current command implementation accepts semantic versions 1–5 from clients built with the current headers, with action availability gated by requested version. Native struct layout is not a stable ABI; old precompiled clients must be rebuilt and a future wire format must be explicitly versioned. Independent regression fixtures reconstruct snapshot versions 1–3 (including saves without the school chair), then round-trip the migrated state using version 4. This tests compatibility separately from the current serializer.

## Environmental conditions
`src/environment.h` introduces an explicitly advanced, persisted simulation clock (standalone start 08:00, no calendar or wall-clock synchronization), local room classification, approximate ambient light, indoor temperature and direct doorway airflow. Six reachable wall switches use the existing device power-state action. The viewer uses the same room-light function to shade geometry and advances simulation time explicitly from bounded frame intervals. Light levels are normalized, not measured lux; this is flat room shading, not dynamic shadow or window simulation. The temperature and breeze are deterministic scenario values, not external weather or a learned emotional appraisal. Open exterior doors affect local temperature/airflow only within a clear direct path. Format 5 saves elapsed time; older snapshots start at the default time and keep added switches in their initialized state. R2 Reality remains responsible for its existing clock and needs; integration must select one time authority instead of double advancing.

## Local sensory queries
The command boundary now accepts explicit environmental and contact observations (semantic version 4). Successful samples return OBSERVED, not APPLIED, and do not advance time, change possessions or generate preferences. Contact modes distinguish a short-range focused surface probe, an existing held object, and physical furniture support; hidden or unreachable targets fail without target data. Static object definitions carry a dominant exterior material. Roughness, compliance and thermal-transfer coefficients are illustrative normalized model parameters, not measured psychophysical values. Ambient temperature is explicitly not surface temperature. Unknown materials remain unknown. No physical sensor claims, hand force simulation, automatic rewards or subjective experience generation. Future Eyes/Hands/Experiences integration must preserve the virtual source and recorded time, and make its own durable event identity.

## Spatial audio foundation
`src/acoustics.h` derives audible cues from the listener's current position and head yaw. Existing fridge, CRT power flags, and open exterior door flags drive five provisional continuous emitters; the fridge hum is a scenario assumption, not a compressor simulation. Inverse-distance-like attenuation and a first-obstruction multiplier use the current collision/visibility geometry. Sources below a threshold are omitted. Sound is not limited to the visual field. The read-only AUDIO sense (command version 5) returns OBSERVED even for silence, with simulation provenance IDs, not claims of recognized sounds. A native renderer produces original deterministic 16 kHz stereo signed-16-bit PCM for a frozen acoustic snapshot, with caller-owned sample indexing and bounded buffers. No media playback, physical microphone access, actual Ears routing, reverberation, diffraction or desktop speaker playback is implemented yet. No new save fields: existing persisted device and door states determine the emitters.

## Action-derived transient audio
Applied movement accumulates horizontal travel and emits a short footstep when the provisional 0.65 m cadence is crossed. Applied door, container and device toggles emit short synthetic clicks from the affected object's geometry. Rejected or unchanged commands do not emit sounds. The bounded eight-event buffer retains only recent transient emitters; elapsed simulation time expires them, and successful snapshot load discards them rather than replaying old actions. This is intentionally not a durable history or Life Log. Large individual walk commands emit at most one footstep at their resulting position (normal viewer motion uses short steps). Transient PCM envelopes use the absolute world-frame clock via lc_audio_frame_at; no query advances time. Continuous sources still derive from persisted object state. Low-level legacy mutations remain available but do not emit command-derived transient audio; use the command boundary for complete behavior.

## Headless visual capture
`src/scene.h` enumerates one shared set of physical parts for visibility rays, the optional raylib viewer and CPU frame capture. `src/frame.h` renders actual 640x480 RGB24 pixels with near-plane clipping, perspective-correct reciprocal depth and room lighting, without any display server or GPU. The caller supplies a 921600-byte RGB buffer and a 307200-float depth workspace. No HUD or object metadata is embedded in pixels. Native tests compare raster depth to sight rays across multiple poses, verify door occlusion and day/night appearance, and check deterministic capture without advancing the clock. Flat box surfaces remain provisional; the optional raylib viewer adds outlines not present in headless capture. No performance claim or actual Eyes connection yet.

## Headless session ownership
`src/session.h` exposes an opaque, independently allocated world session. The host serializes calls, owns time advancement, and may execute any supported semantic command, save/load, or capture RGB, stereo PCM and local environmental values together at a single world revision. Successful actions and nonzero ticks advance the revision; observations and capture do not. Loading stages a fresh house definition, restores the snapshot, and increments a generation and revision, so stale observations from the previous timeline can be distinguished. The session ID is host-supplied; these stamps are not durable event IDs. Capture is not continuous recording: its audio block projects the frozen current acoustic state forward for at most 100 ms, and its image is the actual current frame. The headless core needs no graphics or audio device. Existing low-level and viewer interfaces remain available. No R2 database changes or actual cross-process transport yet.
